## 6. How to run it

**One coordinator session in `C:\dev\crucible`. Lanes are subagents, not second
terminals.**

Two human-driven terminals in one repo is the failure mode the global canon warns
about, and it also breaks the design: **lane blindness is load-bearing**, and a
human who has read two lanes is the leak the architecture exists to prevent.
Subagents have separate contexts by construction, so blindness is enforced
structurally rather than by discipline.

- **Code-writing lanes get worktree isolation.** Six blind lanes cannot share an
  index. Convention: `C:\dev\crucible-wt-L<N>`.
- **The loop is already specified** — `lanes-spec.md` section 7, iterate, check,
  repair, advance, with 7.1 covering what makes it safe unattended.
- **Review at gate boundaries, not at every step.** The gates have teeth: G1
  through G8, four of them failure-mode RUN INVALID. Loop unattended within a work
  item; stop for a human at each gate.
- **`lanes-spec.md` 6.4 lists what the coordinator must never delegate.** Read it
  before delegating anything.

A **second session is worth running only for out-of-repo work** — Devpost fields,
the video script, build-in-public posts in the `linkedin` repo, resume work. Zero
file overlap, so zero coordination cost.

## 6a. This repository is PUBLIC as of 2026-08-20

Decided deliberately, not defaulted into. It is a portfolio artifact, the judge
reproduction path in L6 only works if a stranger can clone it, and the
pre-registration claim (*"each hashed and committed before any measurement"*) is
only checkable by a third party if the commit timestamps are public as they
happen.

**Three consequences, and the second one is the dangerous one.**

**1. The competitive analysis was moved out first.** Scoring arithmetic,
submission-count estimates, prize-lane analysis, the survey of other entrants, and
the post schedule now live in `planning/competitive-analysis.md`, which is
gitignored. `build-spec.md` sections 2-3 and `execution-spec.md` section 5 carry
pointer stubs. Everything else in the repo describes the system; that file
described the contest. **Do not move it back, and do not restate its numbers in a
tracked file.**

**2. `corpus/sealed/` in `.gitignore` is now load-bearing in a way it was not
before.** The `.gitignore` comment has always said the real boundary is IAM, and
that is still true. But the failure mode changed: an accidental `git add -f` on
the sealed corpus used to be an internal mistake fixable by rewriting history.
Public, it is permanent, cloneable, and it **invalidates the sealed-family claim
outright** - which is the single headline number this project produces.

> **L1 owns this and it must exist before D5, when the corpus is authored:**
> a pre-commit hook that refuses any staged path under `corpus/sealed/`. Not a
> convention, not a comment. A hook that exits non-zero. The seal is the one claim
> where a mistake cannot be walked back.

**3. Devpost collaborators are moot.** A public repo needs no access grant, so
`testing@devpost.com` and `cloudhackathons@google.com` do not need adding. Q
commitment `c-20260820-1443-9f60` was closed for this reason. If the repo is ever
flipped back to private, that obligation returns.

**Do not sanitize the correction notes before anyone reads this repo.** The places
where a doc records that a claim was wrong, that the separability proof refuted two
of the specs' own assertions, or that a count drifted between two files written
hours apart are the most valuable material in here. Anyone can produce a clean
spec. Almost nobody produces one that records where it was wrong and who caught it.
