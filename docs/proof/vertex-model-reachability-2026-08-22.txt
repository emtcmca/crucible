WHY THIS FILE EXISTS
--------------------
`vertex-gemma-maas-probe-2026-08-22.txt` (lane L5) concluded that managed Gemma
is unavailable. THE CONCLUSION IS CORRECT AND ITS CONTROL WAS NOT.

That probe used `google/gemini-2.5-flash` in `us-central1` as its control,
reasoning: "=> 200. URL shape, OAuth token, project path and payload are all
correct. So every 404 below is about the MODEL, not about this client."

Two things are wrong with that.

1. `gemini-2.5-*` is DEAD VOCABULARY in this project (`agent.py:49`) and sits
   BELOW the contest's mandatory Gemini 3.5 floor (`CONTEST.md` section 2). A
   proof artifact that prints it invites someone to quote it.

2. More seriously: **the control was taken in a region, and the probes were
   taken in two.** It established `us-central1` was good and then drew a
   conclusion about `global` as well. It never showed `global` worked at all,
   so for half its probes "the 404 is about the model" was unsupported.

Re-running the control found out why that matters.

WHAT WENT WRONG, TWICE, AND THE SECOND TIME WAS MINE
----------------------------------------------------
Every earlier probe - L5's and the one written IN THIS FILE to correct L5's -
used `gemma-4-26b-a4b-it`. **The publisher model id ends `-maas`.** Same class
of error as `gemma-3-27b-it`, which is a version name and not a publisher id.

`us-central1` returns, for the correct id:

    400 FAILED_PRECONDITION
    "Publisher model 'google/gemma-4-26b-a4b-it-maas' in region 'us-central1'
     is only available via global endpoint."

**A 400 that names the fix, where a wrong id returns a 404 that names nothing.**
The two are trivially distinguishable and nobody looked, because the 404 agreed
with what the memo predicted.

THE PART WORTH KEEPING. This file previously said, of the wrong-id probe:
*"That is now demonstrated rather than inferred, and L5's conclusion stands."*
**It was inferred, it was wrong, and the sentence claiming otherwise appeared in
a proof artifact** - written on the same day, in the same repository, as an
overclaim sweep whose entire subject is sentences asserting what the code never
checked. A correction that repeats the defect it corrects is worth more as a
recorded fact than as a deleted one, so the wrong probes stay below.

What actually settled it was a screenshot of the console showing the id in
plain text. Two earlier Gemma screenshots had been read the same evening
without anyone extracting the id pattern from them.
