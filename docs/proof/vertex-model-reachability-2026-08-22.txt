WHY THIS FILE EXISTS
--------------------
`vertex-gemma-maas-probe-2026-08-22.txt` (lane L5) concluded that managed Gemma
is unavailable. THE CONCLUSION IS CORRECT AND ITS CONTROL WAS NOT.

That probe used `google/gemini-2.5-flash` in `us-central1` as its control,
reasoning: "=> 200. URL shape, OAuth token, project path and payload are all
correct. So every 404 below is about the MODEL, not about this client."

Two things are wrong with that.

1. `gemini-2.5-*` is DEAD VOCABULARY in this project (`agent.py:49`) and sits
   BELOW the contest's mandatory Gemini 3.5 floor (`CONTEST.md` section 2). A
   proof artifact that prints it invites someone to quote it.

2. More seriously: **the control was taken in a region, and the probes were
   taken in two.** It established `us-central1` was good and then drew a
   conclusion about `global` as well. It never showed `global` worked at all,
   so for half its probes "the 404 is about the model" was unsupported.

Re-running the control found out why that matters.

CORRECTION TO THE PROBE ABOVE, from the console, 2026-08-22 23:00. The four ids
here are the WRONG SHAPE. Model Garden gives Gemma 3's Model ID as
`publishers/google/models/gemma3`, with `gemma-3-1b-it` as a VERSION NAME - so
`gemma-3-27b-it` and `gemma-3-12b-it` were never publisher model ids and would
404 whatever the project's access. The 404s are real and the conclusion is
right, but this probe was right for a slightly different reason than it stated,
and a lucky answer is not evidence.

WHAT SETTLES IT IS THE CONSOLE, NOT THE PROBE. Eric walked Model Garden the
same evening. The Gemma 3 card offers **Deploy model / Fine tune / Open
Notebook / View Code** and nothing else: no Enable, no "use this model", NO
LICENCE GATE TO ACCEPT. Its own try-it panel reads *"To test this model, you
will need to deploy it to an Agent Platform endpoint"* and reports **"No
endpoints found for selected region."**

**Gemma 3 on Vertex is SELF-DEPLOY. There is nothing to enable.** That is
`gemma-scope.md` section 5's Option A wearing Option B's name, and the memo
predicted it.

`gemma-4-26b-a4b-it` - the only managed-serverless Gemma, announced "over the
coming days" - **is not live yet.** Confirmed by Eric in the console the same
evening.

So there is no human step available, and the 404s were never a permissions
problem. No Cartographer model call is possible and none has been made.
